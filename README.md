# 📓 دفتر يوميات GitHub Pages — PAT + تشفير كامل

موقع ثابت (عربي RTL) + نشر تلقائي عبر GitHub Actions. الدخول بـ PAT + كلمة سر تشفير، محفوظان في **localStorage بهذا المتصفح** (يبقى بعد الإغلاق).

## 🏗️ ريبو عام للموقع + ريبو خاص للبيانات
- **العام** (هذا المجلد): كود الموقع فقط — يُنشر على Pages ولا يحمل أي بيانات.
- **الخاص** (تنشئه فارغاً، وليس فيه أي كود): تُنشأ فيه تلقائياً عند أول حفظ: `data/crypto.json` (الملح) + `data/entries.json` (اليوميات المشفرة) + `media/…` (الوسائط المشفرة).
- الـ PAT يُمنح على **الخاص فقط**، وعند الدخول تختاره من القائمة.

## 🔑 الدخول
1. الصق PAT بصلاحية **Contents: Read and write** → **📦 عرض مستودعاتي** → اختر الريبو من القائمة (فقط ما لديك عليه كتابة).
2. أدخل **كلمة سر التشفير** (4 أحرف على الأقل، والأفضل قوية) → **دخول**.
3. نفس الكلمة مطلوبة كل جلسة. **نسيانها = ضياع البيانات نهائياً** (لا استرجاع).

## 💾 بقاء الدخول (localStorage)
- الـ PAT وكلمة السر والريبو تُحفظ في **localStorage بهذا المتصفح** وتبقى بعد إغلاقه — لا حاجة لإعادة الإدخال.
- ⚠️ هذا يعني أن من يفتح متصفحك يصل للدفتر: استخدمه على **جهازك الخاص فقط** مع قفل شاشة. للمسح الكامل اضغط **🚪 خروج** (يمسح الدخول المحفوظ).
- ملفات العرض (المصغّرات والملفات المفتوحة) تبقى **RAM فقط** وتُمسح بالإغلاق حسب سياسة الذاكرة أدناه — الدائم هو بيانات الدخول فقط.

## 🔐 التشفير (كل البيانات مهما كانت)
- المفتاح: `PBKDF2-SHA256 (120,000 تكرار) + AES-GCM-256`، يُشتق من كلمة السر + ملح محفوظ في `data/crypto.json` (الملح علني وهذا آمن).
- **النصوص**: ملف `data/entries.json` كله مشفّر بصيغة `{"v":1,"iv","data"}` — لا عنوان ولا نص ولا تاريخ مقروء في الريبو.
- **الصور/الفيديو/الصوت**: كل ملف يُشفّر (`IV || ciphertext`) ويُرفع وحده `media/DATE/TIMESTAMP_N_NAME.enc` — لا معاينة بدون كلمة السر حتى لمن يملك الريبو.
- كلمة السر والمفتاح في الذاكرة + `sessionStorage` فقط، ويُمسحان بزر **خروج** أو إغلاق التبويب.

## 🖼️ العرض: مصغّرات بدون تحميل
- وقت الرفع تُولّد **مصغّرات**: صورة 320px للصور، **إطار من الفيديو** + مدته، ومدة الصوت — وتُخزن داخل اليومية المشفرة.
- تصفح القائمة والتقويم **لا يجمّل أي ملف**: المصغّرات تظهر فوراً من `entries.json` (محمّلة أصلاً).
- **كل ملف مخزن مشفراً وحده** (`media/DATE/TIMESTAMP_NAME.enc`) — الضغط على المصغّر يجمّل **هذا الملف وحده فقط**، لا حزمة اليوم كاملة. زر **▶ تحميل الكل** يجمّل مرفقات اليومية دفعة واحدة.

## 🧠 سياسة الذاكرة (RAM فقط — لا قرص إطلاقاً)
- **المرفوعات**: تُزال من الذاكرة **فور نجاح الحفظ** (المصغّرات تكفي للعرض).
- **المحملة للعرض**: تُحذف تلقائياً **بعد 24 ساعة** من فتحها (فحص كل 15 دقيقة + عند الوصول) — لا لحظياً ولا للأبد.
- الخروج يمسح الدخول المحفوظ والذاكرة فوراً. إغلاق التبويب يمسح الذاكرة فقط ويُبقي الدخول.

## ⏳ الرفع والإغلاق
- **لا يستمر الرفع بعد إغلاق المتصفح** — مستحيل تقنياً في موقع ثابت (تتوقف كل السكربتات).
- المغادرة أثناء الرفع تُظهر **تحذيراً** قبل الإغلاق.
- الانقطاع لأي سبب ثم ضغط **حفظ مجدداً يُكمل من حيث توقف**: مسار كل ملف ثابت، والمرفوع فعلاً يُتخطى بدل إعادة رفعه (لا تكرار).

## 📥 العمل دون إنترنت (قائمة انتظار)
- الحفظ يعمل دون اتصال: اليومية + ملفاتها تُحفظ في **IndexedDB على هذا الجهاز** (تبقى بعد إغلاق المتصفح) وتُرفع **تلقائياً** عند عودة الإنترنت (زر **↻ رفع الآن** لليدوي، و🗑 للحذف من القائمة).
- تُشفّر الملفات قبل تخزينها محلياً متى أمكن (الملح محفوظ محلياً بعد أول اتصال). الاستثناء الصادق: أول استخدام **دون أي اتصال سابق** يُخزن خاماً على جهازك حتى لحظة الرفع حيث يُشفّر — جهازك الخاص فقط.
- لا تعمل المزامنة قبل تسجيل الدخول (تحتاج PAT + كلمة السر).

## 📲 التثبيت كتطبيق (PWA)
- افتح الموقع من متصفح الهاتف ← القائمة ← **تثبيت/إضافة إلى الشاشة الرئيسية** (أو زر 📲 داخل التطبيق إن ظهر) — أيقونة دفتر، ملء شاشة، وعمل دون إنترنت.
- **دون إنترنت وبدخول محفوظ**: التطبيق يفتح في **وضع عدم الاتصال** — الكتابة والحفظ المحلي (قائمة الانتظار) يعملان، وعند عودة الاتصال تُحمّل اليوميات وتُزامن القائمة تلقائياً.
- **انقطاع الشبكة لا يمسح دخولك أبداً** — المسح فقط عند رفض المصادقة (توكن خاطئ/بلا صلاحية) أو زر خروج.
- الـ Service Worker يخزّن **ملفات التطبيق فقط** (HTML/CSS/JS/أيقونات). الـ API والوسائط **لا تُخزّن إطلاقاً** — خصوصية كاملة.
- ملاحظة: أيقونات `icons/` مولّدة بسكربت (`make-icons` مؤقت) — لا تعدّلها يدوياً.

## ✏️ اسم وملاحظة لكل ملف
- تحت كل ملف مرفق في صفحة الرفع: حقل **اسم العرض** (يظهر بدل اسم الملف الأصلي ويُستخدم عند التنزيل) وحقل **ملاحظة** (تظهر مع المصغّر وتحت العرض الكامل).
- يُحفظان مع اليومية المشفرة، ويظهران في قائمة الانتظار أيضاً.

## 🗜️ الضغط والرفع
- **الصور**: ضغط تلقائي (تصغير لأقصى 1920px + JPEG جودة 0.82) قبل التشفير.
- **الرفع**: كل ملف يُشفّر ويرفع وحده `media/DATE/TIMESTAMP_N_NAME.enc`.
- **الملفات الضخمة (بلا حد من التطبيق)**: ما تجاوز ~40MB يُقسّم تلقائياً لقطع 20MB (كل قطعة مشفرة مستقلة) ويُجمّع عند العرض/التنزيل — حتى ~500MB (سقف ذاكرة المتصفح). بصراحة: سقف GitHub الصلب ~100MB للملف الواحد عبر API و~1GB لحجم الموقع، فـ"بلا حد" حرفياً مستحيل — لكن عملياً مئات MB تعمل. وعند الفتح يُتحقق من **اكتمال** كل ملف/قطعة (مقارنة بالحجم المعلن) وعند أي نقص يُحمّل الخام عبر `api.github.com` نفسه (`application/vnd.github.raw` — مصادقة كاملة بلا مشاكل CORS): فلا أخطاء "too small" ولا "failed to fetch".
- **الصوت واضح**: زر 🔊 مخصص يفتح اختيار الصوت مباشرة (وأزرار 🖼️ 🎬 للصور والفيديو)، وضغط الصوت الكبير بجودة 96k للحفاظ على الوضوح.
- **⬇️ تنزيل ZIP**: زر تنزيل يجمع ملفات اليومية في ZIP صالح مفكوك التشفير (للنسخ الاحتياطي).
- **بصراحة**: لا شيء يصغّر JPEG/MP4 كثيراً (مضغوطة أصلاً) — التوفير من ضغط الصور. **RAR مستحيل** داخل المتصفح (صيغة مملوكة بلا مشفّر JS) و**7z غير عملي** (LZMA ثقيل) — وZIP المستخرج عند التنزيل يفتح في كل الأنظمة بدون برامج.
- **الفيديو الكبير (أكثر من 10MB)**: **ضغط تلقائي** — إعادة ترميز (720p، و480p للطويل فوق 8 دقائق) ببت-ريت متكيف، بسرعة التشغيل مع نسبة تقدم. **تخطٍّ ذكي**: الصغير المضغوط أصلاً (≤25MB وبتريت منخفض) يُرفع مباشرة دون معالجة. الترميز المفضل H.264 عتاداً (أسرع بمرات على الهواتف).
- **الصوت الكبير (أكثر من 8MB)**: **ضغط تلقائي** بجودة 96k — ويُتخطى إن كان مضغوطاً بكفاءة أصلاً أو أطول من 30 دقيقة.
- بصراحة: الجودة تنخفض قليلاً والضغط يستغرق وقت التشغيل (فيديو دقيقتين ≈ دقيقتان)، وعند تعذّره يُرفع الأصل. التسجيل الصوتي من الموقع مضغوط أصلاً (WebM).

## 🚀 التشغيل (ريبو عام + ريبو خاص)
```powershell
# 1) هذا المجلد = ريبو الموقع العام (كود فقط)
cd D:\Snono-Dev\GHjournal
git init; git branch -M main
git add .; git commit -m "journal: app"
gh repo create GHjournal --public --source=. --push
# الريبو → Settings → Pages → Source: GitHub Actions

# 2) ريبو البيانات الخاص (فارغ تماماً — **بأي اسم يعجبك**، تُنشأ ملفاته تلقائياً عند أول حفظ)
gh repo create my-diary --private
```
3. أنشئ Fine-grained PAT على **ريبو البيانات فقط** → Contents: **Read and write**
4. افتح `https://USERNAME.github.io/GHjournal/` → الصق PAT → **اختر الريبو الذي يعجبك** من القائمة → كلمة السر → دخول (وتستطيع التبديل لريبو آخر في أي وقت بزر 🔄)

## 🔑 ما دور الـ PAT؟ وأين مجلد media؟
- الـ **PAT ليس بوابة للموقع** — بل هو ما يسمح للتطبيق (في متصفحك) بقراءة وكتابة **الريبو الخاص** عبر `api.github.com`. كون الريبو خاصاً يمنع الغرباء من تصفحه/نسخه على github.com.
- **النشر (Pages) قناة منفصلة**: الـ Action يبني نسخة الموقع. كان سابقاً ينسخ كل شيء بما فيه `media/` — **أُصلح الآن**: يُنشر **هيكل التطبيق فقط** (`index/css/js/manifest/icons/sw`)، و`data/` و`media/` **لا تصلان للموقع أبداً**. كل البيانات (اليوميات والوسائط) تُجلب عبر الـ API بالمصادقة حصراً.
- ملاحظة: النسخ المنشورة القديمة تختفي مع أول نشر جديد. سجل git يحتفظ بالملفات المشفرة (غير مقروءة دون كلمة السر).

## 📁 البنية
```
# ريبو الموقع العام (هذا المجلد — بلا بيانات):
index.html   دخول (PAT + كلمة سر) + الدفتر + قائمة انتظار (مكتبة ZIP عبر CDN)
manifest.webmanifest + sw.js + icons/  تطبيق PWA قابل للتثبيت ويعمل دون إنترنت
js/app.js    كل المنطق (تشفير + ضغط + مصغّرات + انتظار + تقويم/بحث/تسجيل)
.github/workflows/deploy-pages.yml  نشر هيكل التطبيق فقط
# ريبو البيانات الخاص (يُنشأ فارغاً — تُبنى ملفاته تلقائياً عند أول حفظ):
data/crypto.json    الملح (علني)
data/entries.json   اليوميات مشفرة بالكامل
media/.../*.enc     ملفات مشفرة فرادى
```
